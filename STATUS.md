# Platform Console Status

The Dashboard now includes a permanent searchable usage-manual page in the lower-left auxiliary area and complete CRUD paths for providers, model deployments, routing policies, Bots, channels, context sources/bindings, capability bindings and schedules. Destructive actions use confirmations and dependency protection.

Primary navigation is grouped into workbench, configuration, operations and system administration. Configuration entities open on list views and enter dedicated create/edit states; advanced fields are only shown in those detail states. Capability management is split into inventory, import/update and builder views. The interaction contract is recorded in `docs/information-architecture.md`.

Version `0.1.0` is deployed. Better Auth accounts, roles, same-origin protected BFF, forced initial password change, all center management pages, local Bot chat, schedules, logs, diagnostics, Browser UI and read-only system assistant are implemented. “插件与扩展” adds Runtime Provider list/detail, Runtime Profile CRUD and cross-center extension list/detail with capability, probe, lifecycle and logs; lifecycle changes are admin-only. Complex forms keep common fields concise and expose advanced settings for provider headers/weights, model capabilities/pricing, channel adapter JSON, context scope, Bot safety modes, schedule retries and capability-binding triggers. Overview probes liveness, readiness and version independently; diagnostics collect only bounded, redacted operational metadata.

The Console information architecture now uses secondary navigation for Model, Capability and Plugin management. Channel configuration no longer exposes internal `lark-sdk-openapi` or `lark-cli-external` registry records. Every primary page has contextual concepts/configuration/effect guidance; wide list rows scroll horizontally without splitting one record across lines, high-density actions use a three-dot menu, and form controls share stable dimensions and baselines. Mutations expose global progress, completion/error feedback and disabled-action reasons. The plugin control-plane model is documented in `docs/plugin-control-plane.md`.

Public HTTPS and loopback SSH-tunnel login use separate Better Auth instances backed by the same database and secret. Only exact loopback hosts receive non-Secure host-local cookies; the public domain retains Secure cookies. Login now verifies `/api/me` before reloading and preserves a visible error when the browser did not establish a session. Nineteen tests pass, including host-bound auth selection and page-guide coverage; both access paths are release acceptance targets.

The information-architecture and interaction repair was deployed to `zwj-ubuntu` on 2026-08-16 after verified backup `20260816T055728Z`. Production acceptance covered all sixteen pages at desktop and mobile sizes, for 32 states total. Every business page exposed one contextual guide, global horizontal overflow and clipped controls were both zero, loopback authentication passed, and all twelve services were healthy after rollout.
